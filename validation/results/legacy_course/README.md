# 旧赛道数据对照说明

## 数据来源与范围

读取当前 run/environment.sh 指定的源码配置 map_zones_config.json，以及 info_transmiting.py 实际导入的 task_to_do_unitree.py。不是 map_zones_config_2.json，也不是其他 task_to_do 变体。

- legacy_course_overview.png / .pdf：主调度区、障碍采点及名义目标序列。
- legacy_course_details.png：各障碍分图，编号对应 legacy_waypoints.csv 的 step。
- legacy_auxiliary_regions.png：zon 辅助框与主调度区域原值对照。
- legacy_waypoints.csv：40 个目标的源码表达式、固定坐标、名义坐标及所在调度区。
- audit.json：源文件 SHA256 和跨调度区固定目标列表。

图使用旧 A/B 赛道坐标：A 为 (0,0)，A→B 为 +x，右侧为 +y，故图上 y 正方向向下。不是 Nav2 map 坐标。A/B 在 PCD 中的坐标未从这些文件中获得，不能据此完成 map 对齐。

## 如何读图

彩色矩形是软件分派区域，并非障碍真实轮廓。彩色采点是 begin_x/begin_y，并不能保证它就是入口前停车点。编号按配置顺序列出，仅用于索引，不保证运行次序。

固定目标通过 begin 加局部目标得到。动态表达式 x/y 表示每次回调中的当前位置，无法离线唯一确定。为了显示大致布局，图中从各障碍 begin 开始，并以此前名义目标作为动态 x/y 的代入值；涉及这种假设的连线使用虚线。跳跃产生的位移、实际控制轨迹、传感器误差及跨区后提前切换均未模拟。固定目标之间的实线也只是连线，不能视作轨迹。

未补造障碍间连接段。原程序按当前位置选区域，未提供单一全赛道顺序列表。默认 route_profile 为 demo，只有两个测试点；本图提取的是 zones 分支的各障碍处理函数。

## 对照现场时优先检查

1. 主区域布局是否对应现场：右侧木桥 A、上方木桥 B/大斜坡/限高栏/沙坑、左侧绕杆、下方高墙/台阶。
2. 每个彩色采点是否对应当初采集的位置。尤其台阶 begin=(0,0)，仅表示配置如此，不能证明曾实际采集。
3. 木桥 B 的两个固定目标 (1.42,-4.08)、(0.92,-4.03) 落入大斜坡调度区；限高栏终点 (-6.95,-3.98) 落入沙坑；绕杆末点 (-3.495,-0.175) 落入高墙。区域切换可能先于原处理函数完成，需检查。
4. zon 的若干木桥/坡道辅助框位于正 y，而主区域位于负 y。当前 Quadruped_Obstacle 不用 zon 分派，不能将这套辅助框当作同一套可靠实物轮廓。
5. 木桥 A 处理函数调用木桥 B 模式，木桥 B 调用木桥 A 模式；名称与底盘模式的对应关系需现场核实，图中保留原障碍名。

## 是否沿用

布局、采点与实际一致时，可以作为重采点和 map 对齐的参考。只有确认旧坐标与 map 的对应关系后，固定目标才可转换；动态目标不能直接当作固定任务点。软件调度区域应重新按新任务逻辑设计，不建议原样当作障碍边界。

本次只读取原配置，生成图表和检查文件；未修改地图、采点数据或控制代码，未启动 ROS 或底盘。
