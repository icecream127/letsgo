ros2_to_stm32:核心代码
	trans.py：坐标系转换，订阅里程计算法的机器人实时坐标，订阅ui数据，记录当前点的坐标，采2点重新建立坐标系，并在以后将里程计的坐标转换到新坐标系上，发布到新的坐标话题上（还订阅了ui的其他数据，可以扩展采每个障碍物的起始点坐标，并更新到配置地图数据的map_zones_config,json文件中去）
	info_transmiting.py：自动化调用代码，订阅坐标系转换后的话题，传入坐标调用task_to_do的控制函数，
订阅串口节点的消息，判断串口是否断开，如果是，就重置机器人的状态参数
	task_to_do.py：非节点，但是被info_transmiting.py节点调用，task_to_do是自动化控制逻辑类，核心控制都写在这里，读取了map_zones_config.json为自动化逻辑初始化数据和参数，控制逻辑最后发布参数，供串口节点订阅
	serial.py：串口转发节点，打开串口，判断串口是否存在，不存在，发布话题告诉机器人重置参数，存在则订阅task_to_do发布的话题，并与电控代码接口一直，转发到串口控制机器人运动
	map.py：可视化地图节点，读取map_zones_config.json静态地图数据，订阅动态机器人坐标，绘制机器人在地图中的位置，实时显示
	ui.py：可视化采点工具，可以采起点终点并发布话题到trans.py，以供坐标系转换，可扩展更新障碍物的起始点
	map_zones_config.json：json文件，存储地图初始数据，可修改
	config.py：非节点，直接运行可以重置json地图数据
	zone_manager.py：调用可以读写json文件

问题1：Could not load library dlopen error: liblivox_lidar_sdk_shared.so: cannot open shared object file: No such file or directory
	这是关于雷达驱动包的报错，问题是编译后的.so文件找不到
解决办法：进入livox_ros_driver2，进入Livox-SDK2/lib/arm64，打开终端
sudo cp liblivox_lidar_sdk_shared.so /usr/local/lib/
sudo ldconfig
将.so移动到系统变量中去，并更新缓存就好了，如果没有.so文件说明驱动包没有编译过，想办法编译一下即可

feature_extract_enable: false

    作用：是否提取边缘/平面特征点。

    调整建议：Mid-360 是固态雷达，点云覆盖非常密集。FAST-LIO2 的强项就是直接处理原始稠密点云。强烈建议保持 false，设为 true 反而会浪费 CPU 且效果不佳。
point_filter_num: 6

    作用：空间降采样倍数（每 N 个点取 1 个点送入算法）。

    调整建议：如果你的算力不够（比如用树莓派或低配工控机），可以调大（比如 8 或 10），这会显著降低 CPU 占用，但可能会丢失细小物体；算力充足且需要极高精度时，可调小（比如 3 或 4）。一般默认 6 即可。
    
max_iteration: 6

    作用：卡尔曼滤波的单步最大迭代次数。

    调整建议：迭代次数越多，位姿解算越准，但耗时越长。通常 4~8 之间最合适，6 是极佳的平衡点。    
    
filter_size_surf: 0.8 和 filter_size_map: 0.5

    作用：分别是当前帧点云和局部地图的体素滤波尺寸（单位：米）。0.5 表示把 0.5x0.5x0.5 米空间内的所有点合并成一个点。

    调整建议：这是你最常调的参数！

        室外大场景/长廊：调大（例如 0.8~1.0），能大幅降低内存消耗，防止建图崩溃。

        室内小房间/需要细节：调小（例如 0.2~0.3），墙面和障碍物会更平滑、更厚实，但对 CPU 压力大。

cube_side_length: 40.0

    作用：ikd-Tree 维护的局部地图块大小（40米）。保持默认即可。    
 lid_topic 和 imu_topic

    作用：订阅的 ROS 话题名。如果跑不起来，先用 ros2 topic list 看看你的雷达驱动发的到底是不是这两个名字。

lidar_type: 1

    作用：1 代表 Livox 固态雷达。绝对不要改。

blind: 0.4

    作用：盲区过滤（单位：米）。忽略距离雷达 0.4 米以内的所有点云。

    调整建议：非常关键！ 如果你的雷达装在机器人车体内部，或者上方有遮挡物，一定要量一下雷达到车体边缘的距离，把这个值设得比车体大一点（比如 0.6 或 0.8）。否则算法会把你自己的车体当成特征点，导致建图瞬间漂移飞车。

scan_rate: 20

    作用：雷达频率。Mid-360 默认是 10Hz，如果你在雷达驱动里改成了 20Hz，这里也要对应。   
acc_cov / gyr_cov (0.25) & b_acc_cov / b_gyr_cov (0.001)

    作用：IMU 的噪声协方差（信任程度）。

    调整建议：如果你发现机器人在原地静止时，地图还在微微发抖或漂移，说明 IMU 噪声太大，可以适当把这些值调大一点（告诉算法“少信 IMU，多信雷达”）。

det_range: 80.0

    作用：最大有效探测距离（米）。

    调整建议：如果你在空旷的室外，可以改成 100.0 增加约束。如果周围全是玻璃或者反光严重，可以调小（比如 40.0）来过滤远处的噪点。

extrinsic_est_en: true

    作用：在线估计外参。

    调整建议：强烈建议设为 true。即使你给的外参不完全准，算法跑起来之后它也会自己慢慢“微调”到最准的状态。

extrinsic_T 和 extrinsic_R

    作用：雷达到 IMU 的平移和旋转矩阵。

    重点：你这里填的 [-0.011, -0.02329, 0.04412] 正是 Mid-360 官方内置 IMU 的标准外参！这意味着你使用的是雷达自带的 IMU，这部分配置非常完美，不要去动它。    
publish 下的各种 en (enable)

    作用：是否把轨迹、地图发给 RViz2 显示。

    调整建议：如果在实际的无人车/无人机上实机部署（不需要看界面），一定要把 effect_map_en、map_en、scan_publish_en 全部改成 false。这能省下惊人的网络带宽和 CPU 资源。只有在电脑上调试的时候才开 true。

pcd_save_en: false

    作用：是否保存全局点云地图（.pcd 文件）。

    调整建议：你想把建好的图存下来用于后续导航（比如跑 Nav2），就改成 true，并确保上面的 map_file_path 路径在你电脑里真实存在（比如你的桌面路径），否则会报错保存失败。    
blind：根据你的机器人尺寸，避免扫到自己。

filter_size_map：建大图调大（防卡死），建小图调小（求细节）。

pcd_save_en：要不要存图。
